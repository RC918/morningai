# Integration Tests for PR Lease Mechanism in MorningAI Orchestrator

## Overview

The PR (Pull Request) lease mechanism is a crucial feature in the MorningAI Orchestrator, ensuring that concurrent worker processes do not duplicate efforts on the same task. Introduced in PR #2916, this feature utilizes an atomic SETNX operation in Redis to manage leases. The integration tests added in PR #2922 aim to validate the functionality and reliability of this mechanism under various conditions.

### Key Features Tested

- **Concurrent Lease Acquisition:** Ensures that when multiple workers attempt to acquire a lease for the same PR, only one succeeds.
- **TTL Expiry:** Tests that leases expire after a set time-to-live (TTL), allowing another worker to acquire the lease.
- **Complete Blocks with Metadata:** Verifies that upon completing a task, workers can store metadata about the PR alongside releasing the lease.
- **Re-acquisition Post-release:** Confirms that once a lease is released, it can be re-acquired by another worker.

## Code Examples

Below are simplified code snippets demonstrating how the lease mechanism is implemented and tested:

### Lease Acquisition Attempt

```python
import redis

r = redis.Redis(host='localhost', port=6379, db=0)
lease_key = f"pr_lease:{pr_id}"

# Attempt to acquire a lease
if r.setnx(lease_key, "worker_id"):
    print("Lease acquired")
    # Proceed with task
else:
    print("Lease already held")
```

### Integration Test for Concurrent Lease Acquisition

```python
from multiprocessing import Process
import time

def attempt_lease_acquisition(worker_id):
    result = r.setnx(lease_key, worker_id)
    print(f"Worker {worker_id}: {'Acquired' if result else 'Failed'}")

workers = [Process(target=attempt_lease_acquisition, args=(i,)) for i in range(10)]

for worker in workers:
```

## Common Troubleshooting Tips

### Lease Not Acquiring
- Ensure Redis server is running and accessible from your service.
- Verify the correct Redis DB is selected and key namespacing (`pr_lease:{pr_id}`) matches across your services.

### Tests Failing Intermitently
- Check if TTL values are appropriately set for your use case; too short TTL might lead to premature lease expiration.
- Ensure your testing environment accurately simulates concurrency; improper setup might lead to false positives/negatives.

### Data Races or Duplicates
- Double-check implementation of atomic operations like `SETNX` in your code.
- Review logs for any indication of multiple workers bypassing the lease check.
