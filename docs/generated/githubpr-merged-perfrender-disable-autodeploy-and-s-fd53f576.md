# Disabling AutoDeploy and Optimizing Dependencies to Reduce Bandwidth

## Summary

This FAQ addresses the steps taken to mitigate the Render bandwidth crisis encountered by the MorningAI platform. With 485GB of the 500GB bandwidth limit used and 5,386 of the 500 pipeline minutes consumed, a critical review revealed that excessive builds were triggered by auto-deployment across multiple services due to a high volume of commits. To counter this, specific changes were implemented to reduce bandwidth and pipeline minute consumption.

## Changes Implemented

### 1. Disabling AutoDeploy for Selected Services

AutoDeploy was disabled for the following services to prevent unnecessary builds from consuming additional bandwidth:

- `braintrust-processor`
- `morningai-orchestrator-api`
- `morningai-worker-dashboard`
- `morningai-ops-agent-worker`

**Code Example:**

For services deployed on Render, you can disable AutoDeploy by adding the following configuration in the `render.yaml` file:

```yaml
services:
  - type: web
    name: braintrust-processor
    autoDeploy: false
  - type: web
    name: morningai-orchestrator-api
    autoDeploy: false
  # Add similar entries for other services as needed.
```

### 2. Moving Testing Dependencies

Testing dependencies, which included heavy items such as Playwright browser binaries (~150MB+), were moved to a separate requirements file (`requirements-dev.txt`). This action was taken to slim down deployment packages and reduce unnecessary bandwidth usage during builds.

**Code Example:**

Split your `requirements.txt` into two files:

1. `requirements.txt` for production dependencies.
2. `requirements-dev.txt` for development and testing dependencies.

```plaintext
# requirements.txt
flask==1.1.2
gunicorn==20.0.4

# requirements-dev.txt
pytest==6.2.4
playwright==1.12.0
```

### 3. Updating Continuous Integration Workflows

CI workflows (`backend.yml`, `test-apps.yml`) were updated to reflect these changes, ensuring that testing dependencies are installed only when necessary, thereby reducing build times and resource consumption.

**Code Example:**

In your GitHub Actions workflow file (e.g., `.github/workflows/backend.yml`), modify the steps to install dependencies conditionally:

```yaml
steps:
- uses: actions/checkout@v2
- name: Set up Python
  uses: actions/setup-python@v2
  with:
    python-version: '3.8'
- name: Install production dependencies
  run: pip install -r requirements.txt
- name: Install development dependencies if needed
  if: github.event_name == 'pull_request'
  run: pip install -r requirements-dev.txt
```

## Common Troubleshooting Tips

### Issues with Dependency Installation

If you encounter issues where certain dependencies are missing during deployment or CI/CD processes, ensure that:

1. You have correctly separated your `requirements.txt` and `requirements-dev.txt`.
2. Your CI/CD workflows are configured to install from both files when necessary.

### AutoDeploy Not Working as Expected

If changes are not being deployed automatically when expected, verify that:

1. The service’s `autoDeploy` setting is configured correctly in your `render.yaml`.
2. There are no conditions or filters in your CI/CD configurations inadvertently preventing deployments.
