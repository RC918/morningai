# Optimizing Render Deployments and Dependency Management in MorningAI

## Summary

This FAQ addresses the recent efforts to optimize Render deployments and manage dependencies more efficiently within the MorningAI platform. The initiative was taken in response to a bandwidth crisis, where 485GB out of an available 500GB was consumed, alongside the excessive use of pipeline minutes (5,386 out of 500). The root cause was identified as the auto-deployment feature triggering excessive builds due to a high number of commits across multiple services.

## Changes Implemented

The following changes were made to address the issue:

1. **Disabling Auto-Deploy for Specific Services**: Auto-deployment was disabled for four critical services to control the frequency of deployments and manage bandwidth usage better. These services include:
   - `braintrust-processor`
   - `morningai-orchestrator-api`
   - `morningai-worker-dashboard`
   - `morningai-ops-agent-worker`

   To disable auto-deploy for a service in Render, you can modify the service's settings in the `render.yaml` file by setting `autoDeploy: false`.

   ```yaml
   services:
     - type: web
       name: morningai-orchestrator-api
       autoDeploy: false
       # other configurations...
   ```

2. **Separating Development Dependencies**: Development-specific dependencies, which added up to over 150MB due to testing frameworks like Playwright and its browser binaries, were moved to a separate requirements file (`requirements-dev.txt`). This action reduces the size of deployment artifacts.

   In your `requirements.txt`, only include production necessities:

   ```plaintext
   flask==1.1.2
   gunicorn==20.0.4
   ```

   And in your `requirements-dev.txt`, include your development dependencies:

   ```plaintext
   pytest==6.2.4
   playwright==1.12.0
   ```

3. **Updating Continuous Integration (CI) Workflows**: CI workflows were updated to reflect the changes in dependency management and deployment strategies. This includes modifications in files like `backend.yml` for backend deployments and `test-apps.yml` for application testing phases.

    Here's an example snippet for installing dependencies selectively based on environment:

    ```yaml
    jobs:
      build:
        runs-on: ubuntu-latest
        
        steps:
          - uses: actions/checkout@v2
        
          - name: Set up Python 3.x
            uses: actions/setup-python@v2
            with:
              python-version: '3.x'
        
          - name: Install dependencies
            run: |
              pip install -r requirements.txt
              if [ "${{ github.ref }}" == "refs/heads/main" ]; then pip install -r requirements-dev.txt; fi
    ```

## Common Troubleshooting Tips

### Deployment Fails After Disabling AutoDeploy

- Ensure that manual deployments are triggered through the Render dashboard or via the Render CLI after significant updates or at regular intervals to keep services up-to-date.

### Missing Dependencies in Deployments

- Double-check that all necessary production dependencies are listed in your `requirements.txt` file.
- For issues related to development dependencies not being available during CI tests, ensure that your CI workflow installs from both `requirements.txt` and `requirements-dev.txt` when appropriate.

### Increased Deployment Times or Failures Post Dependency Slimming

- Verify that no essential libraries or packages were mistakenly moved to `requirements-dev.txt`.
- Ensure that any large binaries or data files not required for production are excluded from deployment artifacts via `.dockerignore` or similar mechanisms.

By implementing these changes, MorningAI aims to significantly reduce unnecessary bandwidth usage and streamline its deployment process while ensuring a smooth development workflow.
