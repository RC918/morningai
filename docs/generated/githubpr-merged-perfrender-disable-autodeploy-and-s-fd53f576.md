# GitHub PR Merged: Performance Improvements in Render Deployment

## Summary

This FAQ addresses the significant update made to the MorningAI platform aimed at mitigating the Render bandwidth crisis, which peaked at 485GB of the allocated 500GB bandwidth and consumed 5,386 of the available 500 pipeline minutes. The root cause identified was the high number of commits (2,514 this month) across four services with `autoDeploy` enabled, leading to excessive builds.

## Changes Made

1. **Disabling AutoDeploy**:
   - For four critical services: `braintrust-processor`, `morningai-orchestrator-api`, `morningai-worker-dashboard`, `morningai-ops-agent-worker`, we've set `autoDeploy: false`. This action prevents automatic deployment on every commit, allowing us to control when and what we deploy more efficiently.

   ```yaml
   # Example configuration snippet for Render service
   services:
     - name: morningai-orchestrator-api
       autoDeploy: false
   ```

2. **Optimizing Dependencies**:
   - Testing dependencies, which included hefty packages like Playwright along with its browser binaries (~150MB+), have been moved to a separate file named `requirements-dev.txt`. This separation ensures that our production builds do not carry unnecessary weight, reducing bandwidth usage during deployments.

   ```bash
   # Moving heavyweight testing dependencies to requirements-dev.txt
   pip freeze > requirements.txt
   echo "playwright" >> requirements-dev.txt
   ```

3. **CI Workflow Adjustments**:
   - We've updated Continuous Integration workflows (`backend.yml`, `test-apps.yml`) to ensure that testing dependencies are installed only when necessary, further optimizing our build process.

   ```yaml
   # backend.yml snippet
   jobs:
     build:
       steps:
       - uses: actions/checkout@v2
       - name: Set up Python
         uses: actions/setup-python@v2
         with:
           python-version: '3.8'
       - name: Install dependencies
         run: pip install -r requirements-dev.txt
   ```

## Common Troubleshooting Tips

1. **Missing Dependencies in Production**:
    - If you encounter errors related to missing packages in production, ensure that all necessary production dependencies are correctly listed in `requirements.txt` and not mistakenly placed in `requirements-dev.txt`.

2. **Automatic Deployment Not Triggering**:
    - Remember that with `autoDeploy` set to false, deployments must be manually triggered within Render's dashboard or via the Render CLI. Ensure you have the latest configurations pulled from the main branch before initiating a deployment.

3. **CI Failures Post-Separation of Dependencies**:
    - Ensure your CI workflows are correctly pointing to `requirements-dev.txt` for stages that require full test suites and other development tools. Adjustments might be needed if your workflows were initially configured with a single requirements file.

4. **Bandwidth Overages Despite Optimizations**:
    - Monitor your usage closely in the initial weeks following these changes. If overages continue, consider reviewing your deployment frequency and strategies for static assets or leveraging additional optimizations like Docker layer caching.
