# GitHub PR Merged: Unconditional `diff_head_sha` Storage for Commit Pinning

## Summary

This FAQ addresses the resolution of an issue where `commit_id` was being set to `null` during GitHub review postings, leading to a diagnostic log entry of `commit_pinning_attempted=False`. The root cause was identified as the conditional storage of `diff_head_sha` within the `if diff_content:` block in the `reviewer_node`. In scenarios where `diff_content` was empty, such as lockfile-only PRs or edge cases involving truncation, `diff_head_sha` would not be stored, causing the `publisher_node` to proceed with a `None` value for `commit_id`.

### Detailed Explanation

The fix implemented ensures that the `diff_head_sha`, which is crucial for commit pinning during code review processes on GitHub, is now stored unconditionally. This change guarantees that even in cases where there is no difference content (e.g., lockfile updates or when diffs are truncated due to their size), the system will still retain the necessary information for commit pinning.

#### Code Example

Before the fix, the logic looked something like this:

```python
if diff_content:
    # Logic to handle diff content
    state.store("diff_head_sha", extract_diff_head_sha(diff_content))
```

After the fix, it has been updated to:

```python
# Store diff_head_sha unconditionally
state.store("diff_head_sha", extract_diff_head_sha(git_diff))
if diff_content:
    # Continue with handling diff content
```

**Note**: The actual implementation may vary depending on how `extract_diff_head_sha()` function and the state management are structured within your project.

- **Commit ID is Null**: If you encounter issues where the commit ID is null in diagnostic logs after this fix, ensure that your local repository is up to date with the latest changes.
