# GitHub PR Opened: Fix for Commit Pinning in Orchestrator

## Summary

This FAQ entry addresses the recent fix implemented in the MorningAI platform related to commit pinning during GitHub review posting. The fix resolves an issue where `commit_id` was being set to `null`, leading to `commit_pinning_attempted=False` in diagnostic logs, specifically within the context of GitHub integrations.

### Root Cause

The underlying problem was identified in the `reviewer_node` logic, where the `diff_head_sha` (a critical piece of data for commit pinning) was conditionally stored. If the `diff_content` was empty, which could occur in scenarios like lockfile-only PRs or edge cases where diffs were truncated, then `diff_head_sha` would not be preserved in the state. This resulted in the subsequent `publisher_node` passing a `None` value for `commit_id` when attempting to post reviews, thereby failing to pin commits correctly.

### Solution Implemented

The fix involves unconditionally storing the `diff_head_sha`, regardless of whether `diff_content` is present. This ensures that even when a pull request contains minimal changes (such as modifications to a lockfile) or when encountering truncation issues, commit pinning can still be successfully attempted.

#### Code Example

**Before Fix:**

```python
if diff_content:
    # Processing diff content...
    state["diff_head_sha"] = extract_diff_head_sha(diff_content)
```

**After Fix:**

```python
# Moved outside of conditional block
state["diff_head_sha"] = extract_diff_head_sha(diff_content or '')
```
