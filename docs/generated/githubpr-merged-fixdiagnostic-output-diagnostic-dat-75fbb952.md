# FAQ: Diagnostic Data Visibility in Render Logs After PR Merge

## Summary

The recent merge of PR #3062 addresses an issue with diagnostic logging identified in PR #3056, specifically within the MorningAI platform's logging mechanism. Previously, diagnostic data passed via the `extra` parameter in Python's logger were not visible in Render's log viewer due to lack of JSON serialization. This fix ensures that diagnostic information such as `raw_comment_structures`, `allowed_lines_sample`, and `payload_structures` is now embedded directly into the message string as JSON, making it visible and useful for debugging purposes in Render's environment.

## Explanation

In the context of web applications and services running on platforms like Render.com, logging is a critical part of monitoring and troubleshooting. However, the default behavior of Python's logging module does not automatically serialize `extra` fields into JSON format, which can limit visibility when using third-party log viewers that expect log messages in JSON.

The solution implemented in PR #3062 involves modifying the log messages to include diagnostic data directly within the message string. By serializing the `extra` fields as a JSON string and appending it to the main log message, we ensure comprehensive visibility of diagnostic data in Render's log viewer.

### Code Example

Before the change, logging might have looked like this:

```python
import logging

logger = logging.getLogger(__name__)

extra_data = {
    "raw_comment_structures": "...",
    "allowed_lines_sample": "...",
    "payload_structures": "..."
}

logger.info("DIAGNOSTIC: LLM raw comment output", extra=extra_data)
```

After applying the fix from PR #3062, it should be updated to:

```python
import json
import logging

logger = logging.getLogger(__name__)

extra_data = {
    "raw_comment_structures": "...",
    "allowed_lines_sample": "...",
    "payload_structures": "..."
}

diagnostic_message = f"DIAGNOSTIC: LLM raw comment output | {json.dumps(extra_data)}"
logger.info(diagnostic_message)
```
