# Passing `source_pr_number` Through the Orchestrator for Improved Deduplication

## Overview

The recent merge of PR #2926 into the MorningAI platform's codebase introduces a significant enhancement in how pull requests (PRs) are handled, specifically in the context of deduplication. This change implements Issue #2918's proposal to extract `source_pr_number` from the webhook context and pass it seamlessly through the orchestrator pipeline. The primary goal is to achieve more precise deduplication of PRs.

### Background

Before this update, functions like `generate_dedup_key()` and `generate_deterministic_branch()` were invoked with `source_pr_number=None`, indicating that the source PR number was not being utilized in deduplication processes. This limitation was noted in the code with a TODO comment, signaling an area for improvement.

### Implementation Details

With PR #2926, the following changes were made:

- **graph.py**: A new parameter, `source_pr_number`, has been added to the `execute()` method, ensuring that this vital piece of information is available throughout the processing pipeline.
- **Deduplication Logic**: The functions responsible for generating deduplication keys and deterministic branch names now incorporate the `source_pr_number`, allowing for finer granularity in identifying and handling duplicate PRs.

And in the deduplication function:

```python
def generate_dedup_key(source_repo, source_pr_number=None):
    if source_pr_number:
        return f"{source_repo}_{source_pr_number}"

        return source_repo
```

This enhancement brings about a more nuanced approach to PR deduplication by:
