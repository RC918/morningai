# Extracting Duplicate API Client Code into Shared Utility

In the development of MorningAI, it's common to encounter scenarios where similar API client code is duplicated across different parts of the application. Consolidating this code into a shared utility not only enhances maintainability and readability but also ensures consistency in how the application interacts with APIs. This guide will walk you through the process of extracting duplicate API client code into a shared utility within the MorningAI platform.

## Comprehensive Explanation

The goal is to identify common patterns or functionalities in your API interactions, such as HTTP requests for GET, POST, PUT, DELETE operations, and abstract these into a centralized module. This module can then be imported and used across your application, reducing code duplication and potential bugs.

### Step 1: Identify Duplicate Code

Start by reviewing your application's codebase for patterns in API calls. Look for repeated logic such as headers setup, error handling, and response processing.

### Step 2: Create a Shared API Utility Module

Within the `RC918/morningai` repository, create a new directory under `src/utils` (if it doesn't already exist) to hold your shared utilities.

For instance, create `src/utils/apiClient.js` if you're using JavaScript:

```javascript
// src/utils/apiClient.js
import axios from 'axios';

const apiClient = axios.create({
  baseURL: process.env.API_BASE_URL,
  headers: {
    'Content-Type': 'application/json',
    // Add any common headers here
  },
});

// Common error handling
apiClient.interceptors.response.use(response => response, error => {
  // Handle common errors here
  return Promise.reject(error);
});

export default apiClient;
```

### Step 3: Refactor Existing Code to Use the Shared Utility

Replace existing API calls with imports from your newly created utility. For example:

```javascript
// Before
axios.get('https://api.example.com/data', { headers: { Authorization: 'Bearer token' } });

// After
import apiClient from '../utils/apiClient';

apiClient.get('/data');
```

### Step 4: Test Your Application

Ensure that your refactoring did not introduce any regressions by running your application's test suite. Manual testing of affected features is also recommended.

## Common Troubleshooting Tips

- **Issue**: API calls fail after refactoring.
  - **Solution**: Double-check the base URL and headers in your `apiClient`. Ensure that any required environment variables are correctly set up.
- **Issue**: Changes are not reflected in the application.
  - **Solution**: Ensure that all instances of direct `axios` usage have been replaced with `apiClient`. Restart your development server to clear any caches.
- **Issue**: CORS errors after deploying changes.
  - **Solution**: Verify that CORS settings on your server are correctly configured to allow requests from your application's domain.
