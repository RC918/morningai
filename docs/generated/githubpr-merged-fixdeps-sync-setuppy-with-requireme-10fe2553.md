# Syncing `setup.py` with `requirements.txt` to Prevent Dependency Downgrade

## Summary

This FAQ addresses the issue resolved in PR #3039 where a discrepancy between `setup.py` and `requirements.txt` led to unintended dependency downgrades, specifically with the `supabase` package. The root cause was that `setup.py` had a hardcoded version of `supabase==2.6.0`, which conflicted with newer versions specified in `requirements.txt`. This problem manifested during deployment on Render, causing version conflicts and downgrades when running `pip install -e .`.

## Root Cause

The issue arises from how Python's package installer (`pip`) handles dependencies listed in `setup.py` versus those in `requirements.txt`. When executing `pip install -e .`, pip prioritizes the versions specified in `setup.py`, potentially downgrading packages to match these specifications even if newer versions were previously installed via `requirements.txt`. The Render logs highlighted this behavior by showing the uninstallation of a newer version of `supabase` to revert to the version hardcoded in `setup.py`.

### Example Log Output

```
Found existing installation: supabase 2.11.0
Uninstalling supabase-2.11.0:
  Successfully uninstalled supabase-2.11.0
```

## Solution

To prevent such issues, it's crucial to ensure that `setup.py` and `requirements.txt` are synchronized, especially regarding version specifications for shared dependencies.

### Code Example

Here is an example snippet from a corrected `setup.py`:

```python
from setuptools import setup

setup(
    name='morningai',
    version='1.0',
    install_requires=[
        'flask>=1.1,<2.0',
        'gunicorn>=20.0,<21.0',
        'supabase>=2.11'  # Ensure this matches the version in requirements.txt
    ]
)
```

And in the corresponding `requirements.txt`, you would have:

```
flask>=1.1,<2.0
gunicorn>=20.0,<21.0
supabase>=2.11  # Match setup.py
```

## Common Troubleshooting Tips

- **Always cross-reference versions** between `setup.py` and `requirements.txt` before commits or deployments.
- Use virtual environments (like venv or conda) to test installations locally before pushing changes.
- For dependency conflicts during deployment, consult the build logs for details on which versions were expected versus what was installed.
- Utilize tools like Pipenv or Poetry that automatically manage dependencies and their versions across files to minimize manual synchronization efforts.
