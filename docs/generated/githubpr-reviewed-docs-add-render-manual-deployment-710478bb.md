# Manual Deployment SOP for Render in MorningAI

## Summary

This FAQ entry is designed to provide comprehensive guidance on the Standard Operating Procedure (SOP) for manual deployments to Render, as outlined in PR #2901. This procedure became necessary following PR #2897, which disabled `autoDeploy` on all Render services to mitigate bandwidth and pipeline cost issues. Here, we cover the pre-deployment checklist, step-by-step instructions, post-deployment verification, rollback procedures, and a troubleshooting guide.

## Pre-Deployment Checklist

Before initiating a manual deployment to Render, ensure you have completed the following steps:

1. **Review Application Changes**: Ensure all changes intended for deployment have been reviewed and merged into the main branch.
2. **Environment Variables**: Confirm that all necessary environment variables are up-to-date in your Render service configuration.
3. **Backup Database**: Take a backup of your PostgreSQL database hosted on Supabase to prevent data loss.

## Step-by-Step Deployment Instructions

1. **Log into Render**: Access your Render dashboard.
2. **Select Your Service**: Navigate to the service you wish to deploy.
3. **Initiate Manual Deploy**:
    - Go to the "Manual Deploys" section.
    - Choose the branch you wish to deploy (typically `main` or `master`).
    - Click "Deploy".

```bash
# Example CLI command for deployment if using Render's CLI tool
render deploy service --service-id <YOUR_SERVICE_ID> --branch main
```

4. **Monitor Deployment**: Stay on the deployment page to monitor progress and resolve any issues immediately.

## Post-Deployment Verification

After deploying:

1. **Check Service Health**:
    - Verify that the service status is "Live".
    - Check application logs for any immediate errors.

2. **Perform Smoke Tests**:
    - Execute basic functionality tests on your application to ensure core features work as expected.

3. **Verify New Features**:
    - Confirm that new features or fixes deployed are functioning in the live environment.

## Rollback Procedure

If you encounter issues with the new deployment:

1. **Identify Last Stable Deployment**:
    - Check previous successful deployments in Render's "Deployments" tab.

2. **Rollback**:
    - Select the last stable deployment and click "Rollback to this Deploy".

```bash
# Rollback via Render's CLI if necessary
render rollback --deployment-id <LAST_STABLE_DEPLOYMENT_ID>
```

## Troubleshooting Guide

### Common Issues & Solutions:

- **Failed Deployments**: Check build logs for errors related to dependencies or compilation issues. Ensure all required environment variables are set correctly.
- **Service Unavailability**: Verify that there aren't any ongoing incidents on Render's status page. Review application logs for unexpected errors.
- **Performance Degradation**: Consider scaling your service or optimizing resource usage if you're experiencing slow response times post-deployment.

For more detailed assistance, visit [Render's Documentation](https://render.com/docs) or consult their support team for specific issues related to their platform.
