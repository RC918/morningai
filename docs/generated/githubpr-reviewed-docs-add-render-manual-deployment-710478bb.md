# Manual Deployment SOP for Render in MorningAI

## Summary

This document serves as a comprehensive guide to the Standard Operating Procedure (SOP) for manual deployments on Render, specifically tailored for the MorningAI platform. The need for this SOP arose after PR #2897, which disabled `autoDeploy` across all Render services as a measure to mitigate bandwidth and pipeline cost issues. This guide includes a pre-deployment checklist, detailed deployment instructions, post-deployment verification steps, a rollback procedure, and a troubleshooting guide.

## Pre-Deployment Checklist

Before proceeding with the deployment, ensure the following:

- [ ] All changes have been thoroughly tested in a development or staging environment.
- [ ] The latest codebase is pulled from the `main` branch of the RC918/morningai repository.
- [ ] Dependencies are up-to-date and compatible.
- [ ] Environment variables and secrets are correctly configured in Render's dashboard.

## Step-by-Step Deployment Instructions

1. **Prepare Your Local Environment:**
   Ensure your local git repository is up-to-date with the remote `main` branch.
   ```bash
   git checkout main
   git pull origin main
   ```

2. **Build Your Project (if applicable):**
   For projects requiring a build step, execute the necessary build commands. For example, for a React frontend:
   ```bash
   npm run build
   ```

3. **Log in to Render CLI:**
   Make sure you're logged into Render's CLI tool. If not, log in using:
   ```bash
   render login
   ```

4. **Deploy Using Render CLI:**
   Navigate to your project directory and deploy using the Render CLI. Specify your service ID and other relevant options.
   ```bash
   render deploy --serviceId=<your_service_id> --type=web
   ```

## Post-Deployment Verification Procedures

After deployment:

- [ ] Verify that the application is running smoothly on Render by accessing your service URL.
- [ ] Check application logs in the Render dashboard for any immediate errors or warnings.
- [ ] Monitor performance metrics available in Render to ensure stability.

## Rollback Procedure

If issues arise post-deployment:

1. Identify the last stable commit ID or tag from your repository.
2. Re-deploy using the stable commit ID or tag through Render CLI:
    ```bash
    render deploy --serviceId=<your_service_id> --commit=<stable_commit_or_tag>
    ```

## Troubleshooting Guide

**Common Issues:**

- **Deployment Fails to Start:** Ensure that all required environment variables are set in Render's dashboard.
- **Service Unreachable:** Verify that there are no network policies or firewall settings blocking access to your service on Render.
- **Performance Issues:** Check if your service's resources (RAM/CPU) need scaling based on the performance metrics in Render.

For more detailed troubleshooting, refer to [Render's documentation](https://render.com/docs).
