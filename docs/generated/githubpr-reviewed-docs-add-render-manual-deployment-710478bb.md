# Manual Deployment SOP for Render in MorningAI

## Summary

This FAQ entry addresses the newly added Standard Operating Procedure (SOP) for manual deployments to Render, following PR #2901 in the MorningAI repository. The necessity for this documentation arose after auto-deployment was disabled across all Render services (via PR #2897) to mitigate bandwidth and pipeline cost issues. The SOP aims to guide developers through the manual deployment process efficiently.

## Pre-Deployment Checklist

Before initiating a manual deployment, ensure the following:

1. **Codebase is Updated**: Confirm that your local repository is up-to-date with the `main` branch.
2. **Tests Passed**: Ensure all unit and integration tests pass on your local machine.
3. **Dependencies Checked**: Verify that all dependencies are correctly listed and up-to-date in `requirements.txt` or `package.json`.
4. **Environment Variables**: Update necessary environment variables on Render's dashboard if any new variables are introduced or existing ones are changed.

## Step-by-Step Deployment Instructions

1. **Log in to Render**:
    - Visit [Render's Dashboard](https://dashboard.render.com/) and log in with your credentials.

2. **Select Service**:
    - Navigate to the service you wish to deploy within the Render dashboard.

3. **Manual Deployment Trigger**:
    - Find the "Manual Deploy" option under settings or overview tab and initiate a deployment.

```bash
# Example CLI command if applicable
renderctl deploy --service-id=<your-service-id> --branch=main
```

4. **Monitor Deployment**:
    - Keep an eye on the deployment logs for any errors or warnings during the process.

## Post-Deployment Verification Procedures

After deploying, perform the following checks:

1. **Application Health Check**: Access your application URL to ensure it's running as expected.
2. **Functionality Test**: Conduct a quick round of critical path testing to confirm core functionalities are operational.
3. **Log Review**: Examine deployment and application logs for unnoticed issues during startup.

## Rollback Procedure

If you encounter issues post-deployment, follow these steps to rollback:

1. **Identify Last Stable Deployment**:
    - On Render's dashboard, navigate to the "Activity" tab of your service and identify the last stable deployment.

2. **Initiate Rollback**:
    - Click on the rollback option next to the stable deployment entry.

```bash
# Example CLI command if applicable
renderctl rollback --service-id=<your-service-id> --to=<stable-deployment-id>
```

3. **Verify Rollback Success**:
    - Ensure that the application is back to its stable state by conducting health and functionality checks as mentioned above.

## Troubleshooting Guide

Here are common troubleshooting tips:

- **Deployment Fails**: Check error messages in logs carefully; often, they provide clear indications of missing environment variables or configuration issues.
- **503 Service Unavailable**: This typically indicates that your application isn't starting up correctly. Review application logs for errors during startup.
- **Timeout Errors**: If deployments time out, consider optimizing build steps or increasing timeout settings on Render if possible.
