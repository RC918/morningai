# Enhanced Logging for Staging Observation in MorningAI

## Summary

With the merge of PR #3047, MorningAI introduces an enhanced logging infrastructure aimed at supporting a 1-week staging observation period. This update is pivotal for monitoring and analyzing the behavior of filtered events, particularly in the wake of the garbage PR fix implemented in PR #3040. The enhancement focuses on capturing additional metadata within logs, thereby facilitating a more detailed observation and troubleshooting process.

## Changes Introduced

The enhancements made to the logging infrastructure include:

- **UNKNOWN Event Logging Enhancement**: Logs for events that are not immediately recognized or categorized by the system now include additional fields: `github_event`, `github_action`, `head_branch`, and `actor`. This improvement aims at providing a clearer context around such events.
  
- **Orchestrator Skip Logging Enhancement**: Similar to UNKNOWN event logging, orchestrator skip actions (triggered by label and branch match conditions) are now logged with enhanced details including `github_event`, `github_action`, `head_branch`, and `actor` fields. This consistency across logging types ensures comprehensive monitoring.

- **Staging Observation Runbook Addition**: A runbook has been added to guide users through the staging observation process, detailing log querying and analysis methods to maximize the utility of the enhanced logging.

### Code Examples

While specific implementation details might vary based on your setup within the MorningAI platform, here’s a general example of how logging has been enhanced:

import logging

def log_unknown_event(github_event, github_action, head_branch, actor):
