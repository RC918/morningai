# Resolving Render Dependency Conflict with a Single Pip Install

## Summary

This FAQ addresses a critical issue that was causing deployment failures on Render due to a dependency resolver conflict involving `httpx`. The problem stemmed from a two-stage pip install process (first for the api-backend and then for the orchestrator), which resulted in `httpx` being resolved to version 0.27.2 initially and not being upgraded when `google-genai==1.52.0` required `httpx>=0.28.1`.

### Changes Made:
- Unified the Supabase version to `2.11.0` in the api-backend (previously `2.6.0`, whereas the orchestrator was already at `2.11.0`).
- Added explicit pins for dependencies: 
  - `httpx>=0.28.1,<0.29`
  - `websockets>=13.0.0,<15.1.0` in the orchestrator requirements.

### Code Examples

To address and resolve this issue, adjustments were made in the `requirements.txt` file of both the api-backend and orchestrator components.

For the **api-backend**:

```plaintext
# api-backend/requirements.txt
supabase==2.11.0
# other dependencies...
```

For the **orchestrator**:

```plaintext
# orchestrator/requirements.txt
httpx>=0.28.1,<0.29
websockets>=13.0.0,<15.1.0
supabase==2.11.0
# other dependencies...
```

### Common Troubleshooting Tips

If you encounter similar dependency resolution issues, consider the following troubleshooting steps:

1. **Review your `requirements.txt` files**: Ensure that there are no conflicting versions specified across different components of your project.
2. **Use Pip's verbose mode**: Run pip install with `-v` or `--verbose` to get more insight into the dependency resolution process.
3. **Test locally before deploying**: Try to replicate your production environment as closely as possible locally and test your installations before deploying.
4. **Consult Render's logs**: If deployment fails, check Render's deployment logs for specific error messages related to dependency conflicts.
5. **Update dependencies regularly**: Regularly updating your dependencies can help prevent conflicts and ensure compatibility.

Remember, resolving dependency conflicts often involves understanding the specific versions required by each package and ensuring they can coexist without issues within your project environment.
