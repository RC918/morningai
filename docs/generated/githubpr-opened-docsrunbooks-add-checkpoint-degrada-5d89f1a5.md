# Handling Checkpoint Degradation in LangGraph Orchestrator

The addition of the `DegradedPersistenceCheckpointer` feature, as introduced in PR #3018, addresses the critical need for detecting, triaging, and resolving checkpoint degradation incidents within the LangGraph orchestrator component of MorningAI. This FAQ aims to provide developers with a clear understanding of operational procedures following the incorporation of this feature.

## Detection Signals

Two primary events signal checkpoint degradation:

- `checkpoint_degraded`
- `persistence_degraded`

These events are instrumental in initiating the detection process for any issues related to checkpoint persistence within the LangGraph orchestrator. Developers can monitor these events through logging mechanisms or integrated monitoring tools.

### Example Logging Configuration

To configure logging for these events, ensure your application's logging settings include severity levels that capture `WARNING` or `ERROR` events, as these are typical levels at which degradation signals would be logged.

```python
import logging

logging.basicConfig(level=logging.WARNING,
                    format='%(asctime)s - %(name)s - %(levelname)s - %(message)s')
logger = logging.getLogger(__name__)

def log_degradation_event(event):
    if event == 'checkpoint_degraded':
        logger.warning("Checkpoint degradation detected.")
    elif event == 'persistence_degraded':
        logger.error("Persistence layer degradation detected.")
```

## Triage Matrix

Upon detection of degradation signals, refer to the triage matrix outlined in the runbook. This matrix considers two critical factors:

- Degradation ratio: The extent to which performance or reliability has degraded.
- PostgreSQL status: The health and status of the PostgreSQL database as it impacts persistence.

The matrix provides guidance on immediate actions based on these factors, ranging from simple restarts to more complex data recovery processes.

### Triage Example

If a `checkpoint_degraded` event is logged and PostgreSQL status checks reveal no underlying database issues, a service restart might be recommended. Conversely, if database problems are detected alongside persistent degradation signals, deeper investigation into database health and potential recovery actions would be warranted.

## Common Troubleshooting Tips

1. **Event Logs**: Always start by examining the logs for any `checkpoint_degraded` or `persistence_degraded` events. These logs can provide immediate insight into the nature of the problem.
2. **Database Connectivity**: Verify that there are no connectivity issues with PostgreSQL. Use psql or another database tool to check connections.
3. **Resource Utilization**: Check system and database resource utilization. High CPU or memory usage can contribute to checkpoint degradation.
4. **Version Compatibility**: Ensure that your version of PostgreSQL is compatible with the current version of LangGraph orchestrator you're using.
