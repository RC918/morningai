# Automated Documentation Update via GitHub PRs

## Overview

MorningAI integrates a feature that allows for automated documentation updates through GitHub Pull Requests (PRs). This process is part of our continuous integration and deployment strategy, enabling developers to maintain and update documentation efficiently. The specific task of verifying the Phase 2 deployment in DRY_RUN mode is aimed at ensuring that the GitHub Review Posting functionality can be safely re-enabled without directly affecting the live environment, following a fix for Out Of Memory (OOM) issues.

## How It Works

When `ENABLE_GITHUB_REVIEW_POSTING` is set to `true`, MorningAI's workflow is configured to post reviews on GitHub automatically. Setting `GITHUB_REVIEW_POSTING_DRY_RUN` to `true` allows this process to run in a test mode where no actual posts are made, providing a safe environment for verification.

### Configuration

To configure your project for DRY_RUN mode:

1. Ensure you have the latest version of the MorningAI platform codebase.
2. Navigate to your project's root directory.
3. Edit or create a `.env` file adding the following lines:

   ```shell
   ENABLE_GITHUB_REVIEW_POSTING=true
   GITHUB_REVIEW_POSTING_DRY_RUN=true
   ```

4. Commit and push these changes to your repository.

### Verification Test Document Addition

To verify DRY_RUN mode, you might add a test document as part of a PR. Here's an example on how to do it:

1. Create a new branch from your main or development branch.
2. Add a new Markdown file under `docs/verification/` with a name like `phase-2-dry-run-test.md`.
3. Add content that describes what you are testing or any relevant information.
4. Commit your changes with a message like: "Add Phase 2 DRY_RUN mode verification test document".
5. Push your branch and create a new PR against your main or development branch.

Example PR creation command:

```bash
git checkout -b feature/phase-2-dry-run-test
# Make your changes...
git add docs/verification/phase-2-dry-run-test.md
git commit -m "Add Phase 2 DRY_RUN mode verification test document"
git push origin feature/phase-2-dry-run-test
```

Then, navigate to `https://github.com/<your_repository>/pull/new/<your_branch>` to create your pull request.

## Troubleshooting

### Common Issues

- **Environment Variables Not Recognized**: Ensure `.env` file is located at the root of your project and correctly formatted.
- **DRY_RUN Mode Not Working**: Verify that both `ENABLE_GITHUB_REVIEW_POSTING` and `GITHUB_REVIEW_POSTING_DRY_RUN` are set to `true`. Also, check for typos.
- **PR Not Triggering Workflow**: Ensure that GitHub Actions or your CI/CD pipeline is configured correctly to trigger on pull request events.

### Tips

- Always double-check your branch names and ensure you're working off the correct base.
- For troubleshooting GitHub Actions workflows, use the "Actions" tab in your GitHub repository to find execution logs.
