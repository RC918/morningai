# How to Manage Render Bandwidth and Pipeline Minutes by Disabling AutoDeploy and Slimming Dependencies

## Summary

This FAQ addresses the critical issue of managing bandwidth and pipeline minutes on Render, particularly in light of the recent bandwidth crisis experienced by MorningAI. With 485GB of 500GB bandwidth used and 5,386 of 5,000 pipeline minutes consumed this month, it's clear that efficient resource management is essential. The root cause was identified as excessive builds triggered by auto deployment across multiple services due to a high number of commits.

## Changes Implemented

To mitigate this issue, two key changes were made:

1. **Disabling AutoDeploy for Selected Services:** The `autoDeploy` feature was set to `false` for four critical services:
   - `braintrust-processor`
   - `morningai-orchestrator-api`
   - `morningai-worker-dashboard`
   - `morningai-ops-agent-worker`

2. **Slimming Down Dependencies:** Testing dependencies, which amounted to over 150MB (including Playwright browser binaries), were moved from `requirements.txt` to a separate file named `requirements-dev.txt`.

### Code Examples

**Disabling AutoDeploy in Render Configuration:**

For disabling auto deployment, you would typically adjust the Render service configuration. While specific details may vary based on how your project is set up with Render.com, the general approach would involve setting the `autoDeploy` flag to `false` within your Render service definition. This might be done through the Render dashboard or via a `render.yaml` file if you're using Infrastructure as Code (IaC).

```yaml
services:
  - type: web
    name: braintrust-processor
    autoDeploy: false
    # Other configurations...
```

Repeat this process for each of the services mentioned.

**Separating Development Dependencies:**

Move heavyweight testing and development dependencies to a separate requirements file to slim down production deployments.

Original `requirements.txt`:

```plaintext
flask==1.1.2
gunicorn==20.0.4
pytest==6.1.1
playwright==1.9.0
```

New `requirements.txt`:

```plaintext
flask==1.1.2
gunicorn==20.0.4
```

New `requirements-dev.txt`:

```plaintext
pytest==6.1.1
playwright==1.9.0
```

## Common Troubleshooting Tips

**Issue**: Deployment fails after disabling autoDeploy.

**Solution**: Ensure manual deployment triggers are correctly set up in your CI/CD pipeline or through the Render dashboard.

**Issue**: Missing dependencies in production environments after slimming down.

**Solution**: Double-check that all necessary production dependencies are listed in `requirements.txt`. Remember, `requirements-dev.txt` is not installed in production environments.

**Issue**: Excessive bandwidth usage persists.

**Solution**: Review your application logs and metrics on Render to identify any unexpected traffic or deployment patterns that could be consuming resources. Consider implementing more aggressive caching strategies or optimizing asset delivery.
