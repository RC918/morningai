# Disabling AutoDeploy and Slimming Dependencies in MorningAI

## Overview

This FAQ addresses a significant optimization within the MorningAI platform, specifically targeting the Render bandwidth crisis that was identified. With 485GB of 500GB used and 5,386 of 500 pipeline minutes consumed, a critical review was necessary. The root cause pinpointed excessive builds due to `autoDeploy` being enabled for multiple services coupled with heavy testing dependencies.

## Changes Made

To mitigate the bandwidth and pipeline usage, the following changes were implemented:

1. **Disabling AutoDeploy**: The `autoDeploy` feature was disabled for four critical services within the MorningAI infrastructure:
   - `braintrust-processor`
   - `morningai-orchestrator-api`
   - `morningai-worker-dashboard`
   - `morningai-ops-agent-worker`

2. **Slimming Dependencies**: Testing dependencies, which amounted to over 150MB including Playwright browser binaries, were moved to a separate `requirements-dev.txt`. This action reduces the load during deployment phases.

### Code Examples

#### Disabling AutoDeploy

For each affected service, the Render configuration file (`render.yaml`) was updated as follows:

```yaml
services:
  - name: braintrust-processor
    autoDeploy: false
    # other configurations remain unchanged
```

Repeat this process for each service listed above.

#### Separating Development Dependencies

Dependencies exclusively required for development purposes were moved from `requirements.txt` to `requirements-dev.txt`. Here's how you might split them:

**requirements.txt**

```plaintext
flask==1.1.2
gunicorn==20.0.4
```

**requirements-dev.txt**

```plaintext
playwright==1.8.0a1
pytest==6.1.2
```

## Troubleshooting Tips

- **Failed Deployments After Disabling AutoDeploy**: Manually trigger deployments from the Render dashboard if changes are not reflecting.
- **Missing Dependencies in Production**: Ensure `requirements.txt` contains all necessary production dependencies. Development dependencies should be isolated to `requirements-dev.txt` only.
- **Service Downtime or Errors**: Check application logs on Render for specific error messages post-deployment. Revert configuration changes if necessary to stabilize services before retrying.
