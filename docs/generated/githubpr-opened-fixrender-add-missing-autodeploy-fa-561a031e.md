# FAQ: Adding `autoDeploy: false` to MorningAI Services

## Summary

In a recent update (PR #2956), we addressed an oversight by adding the `autoDeploy: false` setting to two primary services of MorningAI: `morningai-backend-v2` and `morningai-agent-worker`. This setting prevents automatic deployments on Render, allowing for more controlled deployment processes. This change follows an earlier adjustment (PR #2897) that applied the same setting to several secondary services but missed these crucial ones.

### Why is `autoDeploy: false` Important?

The `autoDeploy: false` setting is critical for services where manual control over deployment timing is necessary. By default, Render auto-deploys changes pushed to the linked branch of your service. While convenient for some scenarios, this behavior might not be desirable for all environments, especially in production or when testing specific versions.

### Code Examples

To apply the `autoDeploy: false` setting manually through Render's `render.yaml`, you would define it within the service configuration like so:

```yaml
services:
  - type: web
    name: morningai-backend-v2
    env: python
    autoDeploy: false
  - type: worker
    name: morningai-agent-worker
    env: python
    autoDeploy: false
```

This configuration ensures that these services will not automatically deploy changes upon git push, requiring manual deployment action instead.

### Common Troubleshooting Tips

- **Service Still Auto-Deploys After Setting `autoDeploy: false`:** Ensure that the configuration changes have been applied and merged into the main branch linked to Render. Also, check if there are any overriding settings directly in the Render Dashboard.
- **Manual Deployment Not Triggering:** Verify that you have the correct permissions on Render and that your service is not paused or facing other issues from the Render side.
- **Changes Not Reflecting After Manual Deploy:** Clear build cache on Render before triggering a new manual deploy. Sometimes cached builds can cause old code to redeploy.

Remember, controlling deployment through settings like `autoDeploy` provides greater flexibility but requires a more hands-on approach to managing your CI/CD pipeline. Always ensure your team is aware of these settings and understands their impact on your workflow.
