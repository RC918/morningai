# Monitoring Fail-Open Events in PR Lease Mechanism

## Summary

In the context of MorningAI's orchestration layer, a recent addition enhances observability around the platform's resilience to Redis outages or errors during lease acquisition for Pull Requests (PRs). This enhancement, merged in PR [#2919](https://github.com/RC918/morningai/pull/2931), introduces mechanisms to monitor and record occurrences where the system defaults to a fail-open state. The fail-open behavior ensures that PR creation can proceed even when Redis, which is integral for managing leases, is unavailable or encounters errors.

### Key Changes

- A new helper function `_record_fail_open_event()` has been implemented. This function serves a dual purpose:
  - Recording breadcrumbs in Sentry to provide contextual information about the fail-open event.
  - Incrementing metrics counters in Redis to quantify these events over time.
- The introduction of `get_fail_open_count()`, a method that allows querying the number of fail-open events within a specified time window. This facilitates monitoring and analysis of the system's resilience and availability.

### Code Examples

**Recording Fail-Open Events:**

```python
def _record_fail_open_event(self):
    # Record a breadcrumb in Sentry for debugging purposes
    sentry_sdk.add_breadcrumb(
        category='fail-open',
        message='Redis unavailable, proceeding with fail-open',
        level='info'
    )
    
    # Increment fail-open counter in Redis
    redis.incr("fail_open_counter")
```

**Querying Fail-Open Event Count:**

```python
def get_fail_open_count(start_time, end_time):
    # Assuming start_time and end_time are datetime objects for simplification
    count = redis.get_range("fail_open_counter", start_time.timestamp(), end_time.timestamp())
    return count
```

### Common Troubleshooting Tips

**Issue: Fail-Open Events Are Not Being Recorded**

1. **Check Redis Connectivity:** Ensure that your instance of MorningAI has connectivity to Redis. Failures to connect might prevent both lease acquisition and metric recording.
   
2. **Sentry Configuration:** Verify that Sentry is correctly configured within your deployment. Missing or incorrect configuration might lead to missing breadcrumbs for debugging purposes.

3. **Metric Counter Increments:** If you're not seeing increments in your `fail_open_counter`, ensure that the counter exists and is accessible within your Redis setup. You may need to manually initialize this counter if it doesn't exist.

4. **Time Window Misconfiguration:** When querying fail-open counts, ensure your specified time window aligns with stored data formats and ranges. Incorrect time windows can result in zero counts being returned.
