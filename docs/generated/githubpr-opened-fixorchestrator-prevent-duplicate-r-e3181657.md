# Preventing Duplicate Reviews with Atomic Claim Pattern in MorningAI

## Summary

This FAQ addresses a crucial fix implemented in the MorningAI Orchestrator to resolve a significant issue causing duplicate reviews due to a race condition. The problem was identified with a 33.3% duplicate rate observed in Scorecard metrics from December 23rd onwards. The solution involves the adoption of an atomic claim pattern using Redis' `SET NX EX` command to prevent multiple workers from posting duplicate reviews.

### Root Cause

The root cause of the duplicate reviews was traced back to the review publisher's reliance on a check-then-act pattern. This pattern first checked if a review had already been posted (`r.exists()`) and, if not found, proceeded to post the review before setting a marker (`r.setex()`) to indicate the post's completion. This approach allowed for a window where multiple workers could assess that a review hadn't been posted and all proceed to post duplicates.

### Solution: Implementing Atomic Claim Pattern

To rectify this issue, we've implemented an atomic claim pattern using Redis. This pattern atomically sets a key if it does not already exist (`NX`) and specifies an expiration (`EX`). Here's how it works:

1. **Atomic Set**: Attempt to atomically set a unique key for the review post with `NX` (Only set the key if it does not exist) and specify an expiration time with `EX`.
2. **Check**: If the atomic set operation is successful (i.e., it returns `1`), proceed to post the review. If it's not successful (i.e., the key already exists), another worker has already claimed the task, and no action should be taken.

#### Code Example

```python
import redis

# Connect to Redis
r = redis.Redis(host='localhost', port=6379, db=0)

# Unique identifier for the review task
review_task_id = "review:12345"

# Attempt atomic claim with NX EX
if r.set(review_task_id, value="claimed", ex=300, nx=True):
    # Proceed to post review as this worker has successfully claimed the task
    post_review()
else:
    # Task has already been claimed by another worker; no action needed
    pass
```

This code snippet demonstrates how to implement the atomic claim pattern with Redis in Python, ensuring that only one worker can claim and execute a particular task at any given time.
