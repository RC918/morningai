# Preventing Memory Exhaustion in ResilientPostgresSaver

## Summary

This FAQ addresses the issue of Out of Memory (OOM) restarts encountered by the `morningai-agent-worker`, specifically during database failure storms. The core problem was traced to memory accumulation caused by improper handling of exceptions within the retry mechanism. This document outlines the root cause, the solution implemented to fix it, and provides guidance for developers to understand and prevent similar issues in their work with MorningAI.

## Root Cause

The issue was identified in the `_retry_with_backoff` method utilized by `ResilientPostgresSaver` in the MorningAI platform. The method was designed to handle retries upon encountering database failures, using an exponential backoff strategy. However, it inadvertently held references to exception objects across retry attempts via the assignment `last_exception = e`. In Python, exception objects include a traceback attribute that retains a reference to the stack frame and all local variables within it at the point of exception. This behavior prevented garbage collection of significant amounts of data, specifically LangGraph state and checkpoint data that should have been released. Consequently, during prolonged database outages, this led to memory accumulation and ultimately resulted in OOM restarts.

## Fixes Implemented

To address this issue, we revised our approach to handling exceptions within the `_retry_with_backoff` method:

1. **Clear Exception References**: After each retry attempt, we explicitly delete the reference to the last exception object to ensure that it can be garbage collected immediately if not needed anymore.
   
   ```python
   try:
       # Attempt operation
   except Exception as e:
       last_exception = e
       # Exponential backoff logic here
   finally:
       del last_exception  # Ensure the reference is cleared
   ```

2. **Reduce Scope of Variable Retention**: We minimized the scope where exception references are held to reduce the risk of retaining large objects unintentionally.

3. **Enhanced Monitoring**: Added monitoring around memory usage patterns for early detection of similar issues in future.

## Common Troubleshooting Tips

- **Memory Usage Monitoring**: Regularly monitor your workers' memory usage. Unexpected increases may indicate retained references or other memory leaks.
- **Exception Handling Practices**: When catching exceptions, especially in loops or retries, be mindful of what is being retained either directly or indirectly (e.g., through traceback).
- **Garbage Collection Debugging**: Utilize Python's garbage collection module (`gc`) for identifying and debugging objects that are not being correctly garbage collected.
- **Profiling Tools**: Use memory profiling tools such as `memory_profiler` for Python to identify unexpected memory consumption.
