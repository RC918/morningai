# Smart PR Filtering for Documentation Updates

## Summary

The MorningAI platform has introduced a smart filtering mechanism to its webhook system for handling Pull Requests (PRs). This new feature aims to reduce unnecessary documentation updates by filtering out PRs that don't require changes to the docs, addressing the issue of "garbage PRs." These are PRs generated by the orchestrator for trivial changes such as dependency updates, Continuous Integration (CI) fixes, or other non-substantial modifications that do not impact the documentation.

## Filter Pipeline

The smart PR filtering feature consists of two main stages:

1. **Semantic Title Filter**: This is a lightweight filter that quickly dismisses PRs based on their title prefixes. It's designed to skip over PRs prefixed with `chore:`, `ci:`, `test:`, `docs:`, `style:`, and `build:`. Since these categories typically do not affect the codebase in a way that requires documentation updates, they are filtered out at this initial stage.

2. **File Path Filter**: This more detailed filter involves an API call to examine the paths of files changed in the PR. If the changes are limited to directories or files not relevant to the project's documentation (e.g., `.github/`, `tests/`), the PR is excluded from triggering a documentation update.

### Example Code Snippet

Below is a hypothetical example of how you might implement the Semantic Title Filter in Python:

```python
def semantic_title_filter(pr_title):
    # Define prefixes that indicate a PR does not need doc updates
    skip_prefixes = ['chore:', 'ci:', 'test:', 'docs:', 'style:', 'build:']
    # Check if PR title starts with any skip prefix
    return any(pr_title.startswith(prefix) for prefix in skip_prefixes)
```

And for the File Path Filter, you might have something like:

```python
def file_path_filter(changed_files):
    # Define file paths or directories to ignore
    doc_irrelevant_paths = ['.github/', 'tests/']
    # Check if all changed files are in ignored paths
    return all(any(file.startswith(path) for path in doc_irrelevant_paths) for file in changed_files)
```

## Common Troubleshooting Tips

- **Webhook Not Triggering**: Ensure your GitHub webhook is correctly configured with the correct payload URL and content type (`application/json`). Also, verify that it's set to trigger on pull request events.
- **Filter Not Working as Expected**: Double-check your filter logic and ensure you're testing with PR titles and file changes that should be caught by your filters. Logging incoming webhook payloads can help debug unexpected behaviors.
- **Performance Issues**: If your implementation seems slow or unresponsive, review your API call efficiency, especially in the File Path Filter stage. Consider caching or optimizing how you fetch and process file changes from GitHub.
